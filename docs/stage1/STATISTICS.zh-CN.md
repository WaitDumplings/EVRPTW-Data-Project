# Stage 1：当前统计与口径

本页只记录当前确定性 building-with-units 方法的最终属性结果。运行方法见[服务器指南](SERVER_IMPLEMENTATION.zh-CN.md)，算法见[Customer 规格](CUSTOMER_METHOD.zh-CN.md)。

当前 11 城属性快照为 `outputs/stage1_building_units_final_20261102/`，包含每栋标准化来源、最终宽松规模筛查和未解决原因。该快照的谱系、源字节、RMS 参数和校准记录随运行产物保存。完整路网与三类地点的最新道路可用数由服务器组件构造另报。

## 1. 固定候选建筑分母

先构造明确 MS–OSM 整栋对应或 MS 复合轮廓细分子栋；以最终 canonical polygon 的内部代表点判断服务域。排除明确非住宅/混合及用途未知但清楚零户数的对象后，保留住宅和其余用途未知建筑，得到候选集合 B。

B 不因 NSI 匹配失败、户数补全失败、来源冲突或最终规模未评估而缩小。无可信 OSM 对应的 Microsoft 对象、独立 OSM 对象和服务域外对象在前置阶段单列，不属于本指标分母。

每栋最终恰有一种来源状态：

- `nsi`：选择一条合法 NSI 代表记录，原户数直接保留；
- `neighbor`：无合法 NSI 代表时，使用通过相似度、分散度和规模规则的邻居估计；
- `unresolved`：最终户数为空，并记录未解决原因。

所有 U>1 的最终准入都要求建筑规模可评估且通过；一户来源支持保留既定例外。规模估计使用 polygon 面积和原始或明确标记的邻居高度，不使用同一 NSI 户数反推的楼层作为独立证据。

建筑属性覆盖率为：

$$
C_{building}=rac{B_{nsi}+B_{neighbor}}{|B|}.
$$

此指标回答“候选建筑有多少得到本方法可用的住宅户数属性”。它不等于全城真实住宅召回率，也不等于道路接入后的可用地点比例。

## 4. 最大户数与逐栋来源

上表最大值来自最终准入建筑。当前各城最大值均来自一条 NSI 代表记录。经纬度、entity ID、所选 fd_id、面积、独立高度/层数及规模代理见 [building_max_units_20261102.csv](building_max_units_20261102.csv)。这张表的坐标用于定位相应 canonical building；完整 polygon 和 NSI 来源链保存在城市产物。

每栋保存 `units_source`、`units_method`、`selected_nsi_fd_id`、`selected_nsi_resunits`、原始/最终户数、`height_original_m`、`height_neighbor_estimated`、`capacity_units` 及 `uncovered_reason`。有选中来源但未通过最终规模筛查时，保留该来源证据，最终 `units_source=unresolved`。

## 5. 标度与门槛的统计来源

清楚的原始 NSI 住宅参考先做固定空间/来源组划分。当前位置、log 面积、log 高度/层数的 RMS 标度只由训练地理近邻比较对拟合；当前 11 城形成 99 个 type/branch 分组，均未使用零 RMS 回退。含垂直信息的 66 组平均平方贡献各 1/3，位置/面积的 33 组各 1/2。

门槛由留出校准参考的相似度和 log 户数 Q90−Q10 共同确定。默认 95% 表示校准支持保留目标；阈值选择不使用目标户数误差。尺度拟合样本数、参考数量、每组实际 RMS 和校准分位数随 `units/metric_scales.csv`、`quality_thresholds.json` 和 `calibration.json` 保存。参考估计只来自固定 train，不把已补全建筑反复加入参考。

## 6. 与道路后可用数、其他组件的关系

Customer 先报告本页属性准入，再报告已完成道路接入的数量及二者交集。道路接入未确认的建筑保留属性与原因，不从本页候选分母删除。`customers/residential_site_manifest.json` 中的 `information_eligible_buildings`、`road_available_buildings`、`cle_available_buildings` 描述后续组件状态。

路网按原生 way、分段物理边、有向 route 边、reference SCC 和剩余用途接入边分别统计。速度按共同 `(u,v,key)` 库存记录 observed/imputed 限速的条数与长度份额。Depot 区分设施成员、园区/独立 canonical 地点与道路可用地点；charging 区分 AFDC 原始成员、canonical 地点、兼容设备与道路可用地点。

建筑属性结果、组件统计和 CLE 组装分别绑定实际输入、方法、配置与输出哈希。最终 `cle_manifest.json` 与 `stage1_validation.json` 描述那次完整 CLE，不由本页属性覆盖率替代。
